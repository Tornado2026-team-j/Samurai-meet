# 機能仕様：写真

## 1. 対象

プロフィールアイコンとチャット添付写真を、安全にアップロード・保存・表示・削除します。

対応要件：FR-004、FR-012、C-003、C-005

## 2. 写真種別

| 種別 | 所有者 | 閲覧者 | 用途 |
| --- | --- | --- | --- |
| プロフィールアイコン | ユーザー | 公開プロフィール閲覧者 | 相手の判断材料 |
| チャット写真 | 送信ユーザー | マッチ参加者 | 会話・待ち合わせ補足 |
| 本人確認書類 | プロバイダー等 | 原則運営・審査領域のみ | 本人確認。チャット写真とは別管理 |

## 3. 処理フロー

1. TypeScript で画像を選択する。
2. MIME、サイズ、解像度をクライアントで事前検査する。
3. 必要に応じてクライアント側で暗号化する。
4. Go API が所有者、マッチ状態、形式、ファイル実体を再検証する。
5. EXIF GPS 等の不要なメタデータを除去する。
6. 非公開ストレージへ保存する。
7. DB に `photos` のメタデータを登録する。
8. 閲覧時は認証済み API または短期 URL を利用する。

## 4. 実装分担

| 処理 | 言語 / 場所 |
| --- | --- |
| 画像選択、プレビュー、進捗 | TypeScript / TSX |
| クライアント暗号化 | TypeScript + native crypto |
| MIME・サイズ・実体検査 | Go |
| EXIF 除去・リサイズ・サムネイル | Go の画像ライブラリまたは専用 worker |
| アップロード認可・削除 | Go |
| メタデータ | SQL / PostgreSQL |
| 本体 | 非公開ストレージ |

## 5. API / DB

- `POST /photos`
- `DELETE /photos/{id}`
- `GET /photos/{id}` または短期取得 URL
- テーブル：`photos`、`messages`

初期上限値は要決定ですが、少なくとも「1 ファイル上限」「1 日あたり容量」「許可 MIME」「最大解像度」を API と UI で一致させます。

## 6. セキュリティ

- 拡張子だけでなくファイル実体を検査する。
- 公開バケットを使用しない。
- EXIF GPS、端末情報、不要なメタデータを除去する。
- ウイルス・不正ファイル検査を行う。
- チャット写真はそのマッチ参加者だけが取得できる。
- 本人確認書類の保存・削除は、チャット写真と別ポリシーにする。

## 7. 受け入れ条件

- 対応形式以外のファイルがアップロードできない。
- 上限サイズを超えるファイルが保存されない。
- チャット参加者以外が添付写真を取得できない。
- EXIF GPS が配信画像に残らない。
- 写真削除後、DB とストレージの双方で公開されない。

## 8. 要確認

- 対応形式、容量、解像度、サムネイルサイズ。
- 自前サーバー保存か、非公開オブジェクトストレージを利用するか。
- 写真を E2EE 対象にするか。
- 削除要求とバックアップからの削除期限。
