# 機能仕様：相互評価・いいね

## 1. 対象

交流後に双方が相手を評価し、その結果を今後のマッチング時の安心材料として利用します。

対応要件：FR-013、C-005、C-006

## 2. 評価フロー

1. マッチが成立する。
2. ユーザーが交流を完了する、またはカードの時間帯が終了する。
3. `matches.status = completed` とする。
4. 各ユーザーが一度だけ相手を評価する。
5. 評価を集計し、プロフィールの公開値へ反映する。

## 3. 評価項目（案）

| 項目 | 内容 |
| --- | --- |
| `rating` | 1〜5 の数値評価。採用可否は要確認 |
| `liked` | いいねを送ったか |
| `comment` | 任意コメント。公開範囲は要確認 |
| `tags` | 「話しやすい」「時間を守った」等の定型評価。採用可否は要確認 |

「いいね数」と「評価平均」は別の指標にします。`likes_count` はいいねの原票から集計し、評価平均は `reviews` から算出します。

## 4. 実装分担

| 処理 | 言語 / 場所 |
| --- | --- |
| 評価画面、入力、送信状態 | TypeScript / TSX |
| 一回限り制約、対象資格、公開範囲 | Go |
| 平均・件数・いいね数の集計 | SQL / Go |
| 評価・いいねの保存 | PostgreSQL |

## 5. API / DB

- `POST /matches/{id}/reviews`
- `GET /users/{id}/rating` またはプロフィールに埋め込む
- `POST /profiles/{id}/like`（採用する場合）
- `DELETE /profiles/{id}/like`（取消を許可する場合）
- テーブル：`reviews`、`profile_likes`、`profiles.likes_count`

## 6. ルール

- 自分自身を評価・いいねできない。
- マッチしていない相手を評価できない。
- 同一マッチ・同一レビュアーの二重登録を拒否する。
- ブロック・通報後も、すでに送信済み評価をどう扱うかは要決定。
- 自由記述を公開する場合は、個人情報・攻撃的内容の検査が必要。
- 不正な大量評価は検知・無効化できるようにする。

## 7. 受け入れ条件

- 交流完了前に評価できない。
- 各ユーザーが一つのマッチを一度だけ評価できる。
- 評価後にプロフィールの集計値が更新される。
- クライアントから `likes_count` を直接変更できない。
- 評価の表示範囲が仕様どおりに制御される。

## 8. 要確認

- 5 段階評価か、定型タグか、単純ないいねか。
- 評価を匿名表示するか。
- コメントを相手へ表示するか。
- 低評価への異議申立て・削除方針。
- 評価をマッチング順位へ利用するか。
